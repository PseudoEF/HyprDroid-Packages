# Публикация пакетов

1. После согласования создайте публичный репозиторий и включите обязательное ревью и успешный PR CI для main.
2. После ревью возьмите точный коммит из main и запустите `python3 tools/package.py build modules/hello-tile dist`.
3. На доверенной машине создайте ключ Ed25519 вне рабочего дерева или возьмите уже утверждённый ключ. Утвердите ID ключа, raw 32-byte публичный ключ и минимальную начальную ревизию для APK.
4. Выпустите артефакт под тегом `hello-tile-v1.0.0` и именем `hello-tile-1.0.0.hyp`. Каждый опубликованный архив версии неизменяем.
5. Подпишите каталог вне CI PR. При следующей публикации повышайте ревизию и передавайте предыдущий проверенный `catalog.payload.json` через `--previous-payload`.

```sh
python3 tools/package.py catalog --key /secure/publisher.pem --key-id github-v1 \
  --revision 1 dist dist/hello-tile-1.0.0.hyp
```

6. Добавьте только `catalog.json` в релиз фиксированного тега `catalog-v1`. Сохраните проверенную копию payload для следующей публикации. Каталог публикуется после бинарных релизов.

Архив `.hyp` — ZIP с корневым UTF-8 manifest.json и Lua entry. Подпись артефакта Ed25519 покрывает точные байты ZIP. Конверт каталога содержит keyId, Base64 payload и hex signature. Ed25519 подписывает ASCII-префикс `HyprDroid catalog v1` с LF, за которым идут точные декодированные байты payload. Payload содержит schemaVersion, repository, возрастающую revision и записи packages. Каждая запись включает полный manifest, sha256, signature, url и status. Для отзыва передайте предыдущий payload, повышенную ревизию и `--revoke <package-id>` при подписи. Не удаляйте старые ID из каталога.

PR CI обладает только правами чтения, собирает пакеты и проверяет целостность ZIP. Публикация выполняется вручную после ревью. Закрытый ключ и учётные данные публикации никогда не доступны PR.
