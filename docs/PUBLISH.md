# Публикация пакетов

## Допуск к публикации

- First-party модули владельца допускаются после успешного обязательного CI, проверки артефактов и явного подтверждения владельцем точного коммита.
- Community-модули требуют независимого ревью. Пока процесс не организован, их публикация запрещена.
- Ветка `main` защищена. GitHub Actions проверяет PR с правами чтения. Подпись и публикация являются отдельным ручным шагом после допуска.

## Сборка и подпись

1. Зафиксируйте точный разрешённый коммит, проверьте успешный обязательный CI для него и убедитесь, что он входит в защищённую `main`.
2. Соберите только из чистого дерева этого коммита. Запустите `python3 tools/package.py build modules/hello-tile dist`.
3. На доверенной машине создайте ключ Ed25519 вне рабочего дерева или возьмите уже утверждённый ключ. Утвердите ID ключа, raw 32-byte публичный ключ и минимальную начальную ревизию для APK.
4. Сверьте Lua и манифест в архиве с исходниками точного коммита и подтвердите SHA-256. Подпись разрешена после этой проверки.
5. Подпишите каталог вне CI PR. При следующей публикации повышайте ревизию и передавайте предыдущий проверенный `catalog.payload.json` через `--previous-payload`.

```sh
python3 tools/package.py catalog --key /secure/publisher.pem --key-id github-v1 \
  --revision 1 dist dist/hello-tile-1.0.0.hyp
```

6. Проверьте подписи Ed25519 каталога и архива публичным ключом из Core, а также SHA-256, манифест и URL в каталоге.
7. Выпустите артефакт под тегом `hello-tile-v1.0.0` и именем `hello-tile-1.0.0.hyp`. Каждый опубликованный архив версии неизменяем. Скачайте его с подписанного URL и повторите проверку.
8. Добавьте только `catalog.json` в релиз фиксированного тега `catalog-v1`. Скачайте публичный конверт и повторите проверку обеих подписей и хеша. Сохраните проверенную копию payload для следующей публикации.

Архив `.hyp` — ZIP с корневым UTF-8 manifest.json и Lua entry. Подпись артефакта Ed25519 покрывает точные байты ZIP. Конверт каталога содержит keyId, Base64 payload и hex signature. Ed25519 подписывает ASCII-префикс `HyprDroid catalog v1` с LF, за которым идут точные декодированные байты payload. Payload содержит schemaVersion, repository, возрастающую revision и записи packages. Каждая запись включает полный manifest, sha256, signature, url и status. Для отзыва передайте предыдущий payload, повышенную ревизию и `--revoke <package-id>` при подписи. Не удаляйте старые ID из каталога.

PR CI обладает только правами чтения, собирает пакеты и проверяет целостность ZIP. Публикация выполняется вручную после допуска по правилам выше. Закрытый ключ и учётные данные публикации никогда не доступны PR.
